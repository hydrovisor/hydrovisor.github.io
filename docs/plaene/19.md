# Plan 19: I1a-03 UC2 Vorlagen Box und Deckel mit Deckelgrafik und Lochnummern

Stand 4.11.2026 · Paket I1a-03 · Klasse Fachlogik ohne Migration (Vergleichspaket Agent Teams, Konzept 12.7 b) · Planer `planer` (Opus 5.5, mittel) · Planfreigabe nicht nötig

## Ziel

Tim erfasst am Schreibtisch unter `#/vorlagen` Boxen (Gefässmodelle) und Deckel oder Platten (Deckeltypen) über den einen Schreibweg `schreiben()`. Beim Tippen von «Löcher je Reihe» erscheint sofort die Deckelgrafik: Loch 1 vorne links, zeilenweise nach hinten, jedes Loch mindestens 48 dp. Die Domänenfunktionen (Lochbild, Randlöcher, Gangkante, Volumen-Vorschlag, Eingabeprüfung, Nutzung) sind so geschnitten, dass I1a-04 (#21, Assistent «Gefäss erfassen») sie unverändert wiederverwendet.

## Datenfluss

1. Formular → `loecherJeReiheLesen(text)` bei jeder Eingabe → `lochbild(reihen)` → `<Deckel reihen loecher kanten serviceOeffnung />` (ohne Speichern, UC2 «Die Grafik erscheint sofort»).
2. «Speichern» → `deckeltypPruefen(eingabe, vorlagenAusTeilen(buendel.teile).deckel)` → bei Verstössen Text am Feld; sonst `schreiben(deckeltypSchritt(eingabe, clientId), { jetzt: new Date(), zeitzone: 'Europe/Zurich' })`. Die `client_id` ist an den Eingabe-Schnappschuss gebunden (Plan 11 Ü1): jede Änderung am Formular erzeugt eine neue, ein wiederholtes Senden derselben Eingabe dieselbe (TO2).
3. Erfolg → `nachErfolg` lädt das Bündel neu → Liste zeigt die Vorlage; Punkt 5 der Einrichtung hakt sich ab (Plan 18 A2, unverändert).
4. Löschen → `nutzendePlaetze()` leer → `schreiben(loeschVorgang(...))`; Korrigieren → `schreiben(korrekturVorgang(...))` (ein Vorgang: Storno der alten, neue Zeile mit neuer `client_id`).

Wiederverwendung in #21: `vorlagenAusTeilen()` für die Auswahl in Schritt 2 und 3, `volumenPruefen()` für das Betriebsvolumen der Belegung (R9.3), `lochbild()` für die Grafik und die Netztöpfe je Loch (`heim_loch_nr` = `Loch.nr`, Grösse = `topfdurchmesser_mm`), `betriebsvolumenVorschlag()` als Vorgabe.
