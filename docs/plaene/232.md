# Plan 232: UC15 Erntekalender, Leiste mit Ernte, Säen in Saatgut

Stand 14.11.2026 · Paket UC15 (`pakete.md`, ausserhalb der Summen; Konzept v1.8 E16, Entscheid 0026) · Klasse

## Ziel

Am Regal öffnet Tim mit «Ernte» in der Leiste den Erntekalender: je aktivem Satz ein Phasenbalken über acht Wochen ab
Montag der laufenden Woche mit Linie «heute», Ernte-Marken und einer Kurzzeile zum nächsten Ereignis. Ein Tipp auf
einen Satz zeigt unten ein Feld mit allen Terminen; «Pflanze öffnen» führt in die Pflanzenmaske, deren «Zurück» in den
Kalender mit derselben Auswahl zurückführt. «Säen» steht neu als oberste Taste in «Saatgut»; die Leiste heisst Heute,
Anlagen, Ernte, Saatgut, Mehr.

## Grundlagen und Regeln

- Konzept v1.8 6.1 UC15, 6.3 (Leiste), 10 (Bausteine `Tabbar`, `Phasenbalken`), Anhang B.2 E16; Entscheide 0025 und 0026.

import type { Zeitzone } from '../zeit.ts';
import type { Phase } from './profil.ts';
import type { Ernteart } from '../pflanzung/belegung.ts';

export const FENSTER_TAGE = 56;
export type PhasenBuchstabe = 'K' | 'A' | 'W' | 'B' | 'F';
export const PHASE_BUCHSTABE: Readonly<Record<Phase, PhasenBuchstabe>>;
// keimung K, anzucht A, wachstum W, bluete B, fruchtbildung_reife F

export type KalenderKennzeichen = 'Phase unbestätigt' | 'Termine noch offen';

export interface KalenderFenster {

  bis: string;        // von + 55
  heute: string;      // kalendertag(jetzt, zeitzone)

export interface PhasenAbschnitt {
  phase: Phase;
  buchstabe: PhasenBuchstabe;

  bis: string;        // letzter Tag (im Fenster)

export type ErnteTerminArt = 'ernte_ab' | 'schnitt' | 'ende';
export interface ErnteTermin { art: ErnteTerminArt; tag: string }

export interface Erntefenster {

export interface KalenderZeile {

  art: string;                // art.name_de
  kulturform: string;
  kulturformName: string;     // KULTURFORM_NAME
  ort: string;                // ortVon() aus ernte.ts, «R-2.3», «R-A1»
  saatdatum: string;

### Datenfluss je Satz

1. **Aktiver Satz** (AK1): `satz` nicht storniert und `pflanzungVonSatz(teile, satz.id)` (aus `fragen.ts`) liefert eine
   Pflanzung. Pflanzungen in Keimung haben in `v_pflanzung_zustand` den Status `aktiv` (02_datenmodell.sql: Status =
   Grund des Abschlusses, sonst `aktiv`), dieselbe Lesart wie `phasenKarten()` und `ernteAufgaben()` (A1).
2. **Stand**: `phasenStand(teile, satzId, jetzt, zeitzone)`; liefert er nichts, fehlt die Zeile.
3. **Abschnitte** (AK2): für jeden Tag `d` von `max(fenster.von, saatdatum)` bis `fenster.bis` gilt
   `phase = phaseAm(teile, { satzId, sorteId, kulturform, saatdatum, direktsaat }, d, jetzt, zeitzone)`;
   `art = 'bestaetigt'`, wenn `d < heute` und `phase === stand.phase`, sonst `'prognose'`. Aufeinanderfolgende Tage mit
   gleicher Phase und Art bilden einen Abschnitt. Tage vor der Saat haben keinen Abschnitt (A2). Keimung ab Saat gilt
   als bestätigt, weil die Saat selbst ein Ereignis ist (A3).
4. **Pflanzung für die Ernte** (AK3): `ernteStand()` je aktiver Pflanzung des Satzes; massgebend ist die mit dem
   frühesten `moeglichAb`, bei Gleichstand bzw. ohne `moeglichAb` die erste nach id. Das ist dieselbe Wahl wie in
   `ernteAufgaben()` (A4).
5. **Ende** (AK3): `voraussichtlichesEnde(teile, pflanzungId, bezug)` für dieselbe Pflanzung mit
   `bezug = umsetzTag(teile, pflanzungId, zeitzone) ?? reservierung.umsetzen_geplant_am ?? reservierung.umsetzen_vorgabe_am`
   aus `v_reservierung_aktiv`, sonst ohne Bezug; das ist die Wahl aus `topfPrognose()` (A5).
6. **Erntefenster**: `ernteart = ernteStand.ernteart ?? ende.ernteart`. Einmalig: `ernteAb = ernteStand.moeglichAb ?? ende.endeAm`
   (vor dem Umsetzen kennt `ernteStand()` keinen Bezug, `voraussichtlichesEnde()` rechnet dieselbe Regel R11.1 mit dem
   geplanten Umsetztag), `endeAm = ende.endeAm`. Mehrfach ohne Teilernte: `ernteAb = ernteStand.moeglichAb`; mit
   Teilernte: `naechsterSchnitt = ernteStand.moeglichAb`; `endeAm = ende.endeAm`. Fehlende Werte bleiben `undefined`.
7. **Marken**: Termine aus `ernteAb`, `naechsterSchnitt`, `endeAm` (bei einmalig nur `ernte_ab`, weil Ende = Ernte) mit
   `fenster.von ≤ tag ≤ fenster.bis`; der früheste spätere Termin wird `spaeter`. Termine vor dem Fenster erscheinen
   nur in der Kurzzeile («Ernte möglich seit 4.3.») (A6). Keine weiteren Schnitte über den nächsten hinaus (A7).
8. **Kennzeichen** (AK4): «Phase unbestätigt», wenn `stand.naechste?.typisch` vorhanden und `< heute`; «Termine noch
   offen», wenn `stand.naechste?.typisch` fehlt und keiner von `ernteAb`, `naechsterSchnitt`, `endeAm` vorhanden ist (A8).
9. **Nächstes Ereignis** (AK5): bei «Phase unbestätigt» `{ art: 'wechsel', tag: typisch, unbestaetigt: true }`; sonst
   der früheste Tag aus `naechste.typisch` (Wechsel) und den Ernteterminen, bei gleichem Tag in der Folge wechsel,
   ernte_ab, schnitt, ende; ohne Termin `undefined`.
10. **Sortierung** (AK5): Gruppe 0 = unbestätigt, 1 = mit Datum, 2 = ohne Termin; innerhalb nach `naechstes.tag`, dann
    `ort` (`localeCompare('de', { numeric: true })`), dann `sorte`, dann `satzId` (feste Folge für gleiche Daten).

### Texte (Kurzzeile `kurz`, A9)

Teil Wechsel: unbestätigt «<Phase> fällig seit <T.M.>»; Wechsel heute «<Phase> ab heute»; sonst «<Phase> ab <T.M.>»;
letzte Phase oder ohne typischen Tag kein Teil. Teil Ernte: «Ernte ab <T.M.>» (ab heute), «Ernte möglich seit <T.M.>»
(vor heute), «nächster Schnitt ab <T.M.>», ohne Erntetermin «Ernte offen». Zusammengesetzt mit « · ». Mit Kennzeichen
«Termine noch offen» lautet die Kurzzeile «Ernte und Ende ohne Termin». Phasennamen aus `PHASE_NAME`, Daten über
`tagKurz()`.

## Maske `Erntekalender` (`#/ernte`, `#/ernte/<satzId>`)

- Hauptseite mit Leiste (`leisteZiel` → `'ernte'`), `main.hv-seite.hv-kalender` mit `data-density="regal"`, Daten aus
  `useBuendel()`, `jetzt()` aus `bundeldaten.ts` (Date.now nur in der Oberfläche), Rechnung `useMemo` über
  `erntekalender(buendel.teile, jetzt, ZEITZONE)`.
- Kopf: h1 «Erntekalender», rechts «<Wochentag> <T.M.> · n Sätze». Legende, Achse, Liste `ul` mit je einem
  `button.hv-kalender-zeile` (`aria-pressed`, mindestens 68 dp): Kopf «<Art> <Sorte>» und Ort, `Phasenbalken`,
  Kurzzeile, Kennzeichen. Zugänglicher Name «<Art> <Sorte>, <Ort>, <Phase> <phasenText>, <kurz>[, Kennzeichen]».
- Leer: «Kein Satz aktiv. Säen findest du unter Saatgut.» mit Link «Saatgut öffnen» (A14).
- **Auswahl in der Adresse** (A15): Tipp auf eine Zeile ersetzt die Adresse mit `location.replace('#/ernte/<satzId>')`
  (kein Eintrag im Verlauf), erneuter Tipp oder «Feld schliessen» mit `#/ernte`. Eine unbekannte oder nicht mehr
  aktive `satzId` zeigt den Kalender ohne Feld.
- **Feld** `section.hv-kalender-feld` (`aria-label` «Termine des Satzes»), fest unten über der Leiste
  (`bottom: var(--hv-leiste-hoehe)`), Titel «<Art> <Sorte>», `dl` mit Kulturform; Ort; Saat «<Wochentag> <T.M.> · Tag n
  seit Saat»; Phase «<Phase> · <phasenText>» (bei letzter Phase « · letzte Phase»); Nächstes «<Phase> voraussichtlich ab
  <T.M.>» bzw. «<Phase> fällig seit <T.M.>» mit Zusatz «möglich ab <T.M.>, spätestens <T.M.>» (fehlende Teile
  entfallen), sonst «Termine noch offen»; Ernte je Wert «ab <T.M.> (Prognose)», «nächster Schnitt ab <T.M.>», «Ende
  <T.M.>» oder «Termine noch offen» je fehlendem Wert, dazu «einmalig, danach frei» bzw. «Mehrfachernte». Knöpfe
  nebeneinander, umbrechend: «Feld schliessen» (`secondary`), «Pflanze öffnen» (`primary`, Link
  `#/pflanze/<pflanzungId>?von=ernte`). Unter der Liste ein Platzhalter in Höhe des Felds, damit die letzte Zeile
  erreichbar bleibt; beim Öffnen mit Auswahl scrollt die Maske die gewählte Zeile in den sichtbaren Bereich über dem
  Feld.
- **Pflanze**: Mit `von === 'ernte'` steht im Kopf neben «Pflanze» der Link «Zurück» nach
  `#/ernte/<satzId der Ansicht>` (ohne Ansicht `#/ernte`). Die Pflanze bleibt Unterseite ohne Leiste. Auch die
